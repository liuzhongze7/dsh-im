# 有度(Youdu)渠道能力补齐清单

> 研究结论（requirements / 能力切片）。目标：在 dsh-im 有度渠道"连接 + 收发已打通"的基础上，
> 把能力补齐到与飞书/QQ 对齐，复用 `src/channels/shared` 共享语义层，并参考 `@youdu/openclaw-youdu`
> （`D:\Youdu\Client_Code\plugin`）已有能力。本文档是 t2（核心命令补齐）与 t3（交互与流式补齐）实现的输入。

- 调研范围：`dsh-im/plugin-src/host/channels/{youdu,feishu,qq,shared}` 与 `dsh-im/src/channels/{youdu,qq,feishu,shared}`
- 参照实现：QQ 渠道 `src/channels/qq/qq-bridge.mjs`（命令/交互最完整）、飞书 `src/channels/feishu`（群聊/卡片交互）
- 参考协议：`@youdu/openclaw-youdu` 的 `src/{channel.ts, dm-policy.ts, group-policy.ts, message-sender.ts, message-prepare.ts, media.ts}`

## 1. 现状（有度渠道当前能力）

有度渠道已经有最小闭环：一个 bot 对应一个 `YouduRuntime`，持有 `YouduSocket`（WebSocket，`/cgi/bot/wss`）。
入站消息帧 `msg_callback` → `YouduBridge.accept()` 解析 → `askInWorkspaceSession` 交给 Harness → `respond_msg` 回传。

### 已实现（现状基础，不要重复建设）
| 能力 | 位置 |
| --- | --- |
| WebSocket 连接/鉴权/重连/心跳 | `youdu/protocol.mjs`（`YouduSocket`） |
| 入站解析（text/图片/文件/音频/视频附件） | `youdu/inbound.mjs`；`src/channels/youdu/inbound.mjs` 注释明确"最小闭环" |
| 会话复用/绑定 | `youdu/youdu-bridge.mjs` → `askInWorkspaceSession`（`shared/workspace-session.mjs`） |
| 最小命令（仅私聊、仅 `/new` `/help` `/status`） | `youdu/youdu-bridge.mjs` `#process`（硬编码三个命令） |
| 入站图片/文件预处理 | `shared/image-prompt.mjs`、`shared/inbound-file.mjs` |
| 图片非视觉模型回退 | `shared/semantic/reply-reference.mjs`（promptContentForInboundMessage） |
| 失败提示（简化版） | `shared/message-failure.mjs`（`setLastMessageFailure`/`messageFailureText`） |
| 连接测试 + 主动投递文本 | `youdu/youdu-controller.mjs` `sendConnectionTest`；`youdu/youdu-runtime.mjs` `sendProactiveText` |
| 访问控制（极简：仅私聊 ownerUserId 白名单） | `youdu/youdu-bridge.mjs` `#isSenderAllowed` |

### 关键缺口（一句话）
有度渠道**只接入了共享语义层的"会话/图片/文件/失败提示"这一小撮**，
命令、审批、提问、流式、上下文增强、访问策略、群聊、主动投递（媒体/产物回传）**全部缺失或未接线**。

### 一个直接证据
`shared/message-failure.mjs` 等 8 个共享模块被有度引用，而 `shared` 目录下 30+ 模块中
`model-command / preset-command / workspace-command / compact-command / history-command /
control-command / batch-input / harness-approval / harness-question / context-enhancement /
inbound-access / access-policy / command-permission / status-reaction / editable-message-stream /
session-title / session-reply-recovery / harness-session-binding / semantic/delivery /
semantic/artifact / file-download / connection-test / agent-preset / bot-workspace-store` 均未被有度使用。

## 3. 能力切片清单（交付给 t2 / t3）

> 每片：`缺失能力`、`可复用共享模块/文件`、`需接通的基础设施`、`验收要点`。
> 命令处理统一应像 QQ 那样做一个"命令识别器"（isXxxCommand → runXxxCommand），并遵循"命令只在被
> addressed（私聊，或群聊被 @）时执行"、`isSharedLocalCommand` 权限门控、失败走
> `setLastMessageFailure + messageFailureText`。

### 切片 A —— 核心命令补齐（t2 主体）

| 命令 | 可复用模块 | 需接通的基础设施 |
| --- | --- | --- |
| `/model [序号或完整ID] [推理等级ID]` | `shared/model-command.mjs`（`isModelCommand`/`runModelCommand`） | 传递给 runModelCommand 的 harness/state/key/`isDirect` |
| `/models` | model-command | 同上 |
| `/reasoning [序号、等级ID或--default]` | model-command | 同上 |
| `/reasoninglist 或 /reasonings` | model-command | 同上 |
| `/preset [序号或完整ID]`、`/preset --default` | `shared/preset-command.mjs`（`isPresetCommand`/`runPresetCommand`） | agent-preset 目录（`shared/agent-preset.mjs`） |
| `/presetlist 或 /presets` | preset-command | 同上 |
| `/workspace 序号或绝对路径` | `shared/workspace-command.mjs`（`runWorkspaceCommand`/`isWorkspaceCommand`） | 工作区存储（`shared/bot-workspace-store.mjs`） |
| `/workspacelist` | workspace-command | 同上 |
| `/session SessionID 或当前工作区序号` | `shared/workspace-session.mjs` + workspace-command | 会话绑定 + 会话绑定锁 |
| `/sessionlist 或 /sessions [序号|路径] [--limit N]` | `shared/workspace-command.mjs`（`parseSessionListArgument`/`splitWorkspaceCommandMessage`） | 会话列表读取 |
| `/history [数量]`（默认 3，最多 5） | `shared/history-command.mjs`（`isHistoryCommand`/`runHistoryCommand`） | 会话历史读取 |
| `/compact` | `shared/compact-command.mjs`（`isCompactCommand`/`runCompactCommand`） | harness/state/key |
| `/stop` | `shared/control-command.mjs`（`isControlCommand`/`runControlCommand`） | control.owner/key；需在 askOptions.control 传入 `{ owner: this, key }` |
| `/steer 补充指令` | control-command | 同上（纠偏当前任务） |
| `/batch`（仅私聊，≤10 条） | `shared/batch-input.mjs`（`isBatchInputCommand`/`BatchInputManager`/`batchInputBusyMessage`/`batchInputGroupUnsupportedMessage`） | 群聊返回 `batchInputGroupUnsupportedMessage`；提交后当作普通消息入队 |
| `/send`（提交批次） | batch-input | 同上 |
| `/cancel`（取消批次） | batch-input | 同上 |
| `/version` | 渠道常量（参照 QQ） | 无 |
| `/new /help /status` | 已有（保留，但改为走统一命令识别） | 无 |

**验收要点（切片 A）**
- 私聊下 `/models` 能列出模型；`/model 2` 能切换；`/model` 能显示当前；`/reasoning` 能读/切等级。
- `/presetlist` 列出 preset；`/preset 2`、`/preset id:<id>`、`/preset --default` 生效。
- `/workspacelist` 列出工作区；`/workspace 1` 切工作区并在后续会话生效。
- `/sessionlist` 列出会话 ID+标题；`/session <id>` 把当前聊天绑定到指定会话。
- `/history 3` 显示最近 3 条（默认 3 / 上限 5）；越界/非数字有提示。
- `/compact` 压缩后能继续对话。
- `/stop` 立即停止当前 turn（返回"已停止。"）；`/steer 补充说明` 能纠偏正在执行的任务。
- `/batch` 开始收集，最多 10 条，`/send` 提交合并为一次，`/cancel` 取消；群聊触发 `/batch` 返回群聊不支持提示。
- 命令在**群聊未被 @ 时不应执行**；无权限用户执行命令返回 `COMMAND_PERMISSION_DENIED_MESSAGE`。
- 任一命令失败都走 `messageFailureText(failure)` 回传，不抛未捕获异常。

### 切片 B —— 交互补齐（审批/提问）（t3 主体）

| 能力 | 可复用模块 | 接通方式 |
| --- | --- | --- |
| 审批 | `shared/harness-approval.mjs`（`HarnessApprovalQueue`/`harnessApprovalText`/`validHarnessApproval`/`harnessApprovalDecision`） | 在 `askInWorkspaceSession(askOptions.onInteraction)` 里识别审批类交互，`approvals.claimReply(...)` 判定回复归属，`approval.process(...)` 串行；`control: { owner, key }` 传入。参考 qq `#approvals` 用法 |
| 提问 | `shared/harness-question.mjs`（`validHarnessQuestion`/`harnessQuestionText`/`harnessAnswerForQuestion`） | `#pendingInteractions` 记录进行中的提问；`#processInteractionReply` 消费文字回复；`canClaimInteractionReply` 防串话；重复回答返回"已在其他客户端处理" |
| 交互取消/清场 | — | `#cancelPendingInteraction(key)`、`#approvals.closeRoute(key)`（见 qq `#processFastCommand`/`#process` finally 与 `#pendingInteractions`） |

**需配套的桥接器（qq 有、youdu 缺）**
- 将 `askInWorkspaceSession` 的 `askOptions` 扩展为携带 `onInteraction` / `onInteractionResolved` / `progressMode: 'all'` / `onUpdate`。
- 新增 `#pendingInteractions` Map、`#approvals`（`HarnessApprovalQueue`）、`#cancelPendingInteraction`、`#handleInteraction`、`#handleInteractionResolved`、`#processInteractionReply`。
- `status` 增加交互相关字段（`messagesRejected`/`lastRejectedAt` 等，对齐 qq）。

**验收要点（切片 B）**
- Harness 发出审批类交互时，有度渠道能展示可读的审批文本并能接收用户"同意/拒绝"（或文本）回复，串行不串话。
- Harness 发出提问类交互时，用户槽位的文字会被正确消费并回填；重复/非预期回复按"已在其他客户端处理"处理。
- 交互结束（提交/取消/超时）后能继续普通消息；`/stop` 能中断进行中的交互并清场。
- 群聊中交互要求 @ 才消费（`requiresMention`），否则不误领。

### 切片 C —— 流式回复与状态（t3 主体，需有度适配）

| 能力 | 可复用模块 | 说明 |
| --- | --- | --- |
| 流式回复 | `shared/editable-message-stream.mjs`（`createEditableMessageStream`/`splitMessageText`） | **有度 WebSocket 无"编辑已发消息"原语**（`sendReply` 是 `respond_msg`、`sendMessage` 是 `send_msg`，openclaw 亦无 update/edit/recall）。需先做协议探测；若确无编辑能力，则降级为"分片顺序发送"或干脆走 markdown 一次性回复（对齐 QQ 注释：部分 C2C 客户端不渲染 stream_messages，故 QQ 用标准 Markdown 交付）。**这是本清单里唯一需要"能力探测/降级"的切片** |
| 流式状态（thinking 反应） | `shared/status-reaction.mjs`（`beginStatusReaction`） | 同样取决于有度是否支持对已发消息加反应/状态；不支持则降级为忽略或文本提示 |
| 交付凭据 | `shared/semantic/delivery.mjs`（`createDeliveryReceipt`/`providerMessageIdsFor`/`createTextDeliveryBlock`） | 记录每条回复的 provider messageId，供幂等/回执 |
| 回复内容拼装 | `answerTextForDelivery`（qq 内部函数，可抽到 shared 或你有度本地实现） | 文本 + 产物清单 + 工具错误汇总（`toolErrors`，见 qq `#process`） |

**验收要点（切片 C）**
- 有 `onUpdate` 时能在回复过程中推送中间更新；若降级为分片/一次性，仍保证最终内容完整、无重复。
- 每次回复生成 delivery receipt 并记录 `providerMessageIds`。
- 工具调用失败时，最终回复附上"工具「{name}」未成功…"的汇总（对齐 qq 的 `toolErrors`）。
- 产物/文件与文本分离交付，纯产物路径走 `deliverOutboundArtifacts`（见切片 D）。

### 切片 D —— 访问控制与命令权限（跨切片，建议纳入 t2，连同群聊一并做）

| 能力 | 可复用模块 | 接通方式 |
| --- | --- | --- |
| 入站访问策略 | `shared/inbound-access.mjs`（`evaluateInboundAccess`/`COMMAND_PERMISSION_DENIED_MESSAGE`） | 替代现有 `#isSenderAllowed` 简化逻辑；在 `accept()` 里对 addressed 消息做 `evaluateInboundAccess`，返回 `command-not-allowed` 时回 `COMMAND_PERMISSION_DENIED_MESSAGE` |
| 访问策略模型 | `shared/access-policy.mjs`（`createAccessPolicy`/`evaluateAccessPolicy`/`DEFAULT_ACCESS_POLICY`/`validateAccessPolicy`） | 生成策略对象（direct/group 双类型、open/allowlist）；host 侧 `plugin-src/host/channels/shared/access-policy-{rpc,production}.mjs` 已提供 RPC/生产接线 |
| 命令权限 | `shared/command-permission.mjs`（`isSharedLocalCommand`） | 命令是否允许该用户执行（用于"可发普通消息但不可执行命令"） |
| 群聊访问策略 | 参考 `@youdu/openclaw-youdu` `src/group-policy.ts`（groupPolicy open/allowlist/disabled + groupAllowFrom + 每个群 sender allowlist）与 `src/dm-policy.ts`（dmPolicy + pairing） | 有度作为独立渠道回落到 shared access-policy 即可；openclaw 的群/私聊策略可作为文案与默认值参考 |

**验收要点（切片 D）**
- 私聊：仅 owner/白名单可触发；被拒绝的消息 count 为 `messagesRejected`。
- 群聊：按群策略 + 群内 sender allowFrom 判定；未授权者不能触发，也不能执行命令。
- `command-not-allowed`（有发消息权但无命令权）返回 `COMMAND_PERMISSION_DENIED_MESSAGE`。
- 策略可配置化（open/allowlist/disabled），默认值与 `DEFAULT_ACCESS_POLICY` 一致。

### 切片 E —— 群聊能力（跨切片，与切片 A/D 联动）

参照 qq：
- **addressed 判定**：`message.kind !== 'group' || message.rawEventType === 'GROUP_AT_MESSAGE_CREATE'`。有度入站帧需识别"群聊 + 被 @ bot"（参考 openclaw group-policy.ts / message-prepare.ts 对 `atUser`/`at` 字段的解析；若有度帧中 group 消息无 rawEventType 等价物，需用 `body` 中是否@bot 判定）。
- **会话路由**：`conversationKey` 已区分 `group:${chatId}` 与 `direct:${senderId}`，但群聊下命令与本次会话应绑定到"群"而非"单个发送者"；且同一群内不同用户的角色/权限要区分。
- **回复路由**：`sendReply(target, ...)` 需要 target 携带正确的群 chatId（现 runtime 的 `sendReply` 只回 `reqId`，未显式带 chatId——需确认 `respond_msg` 是否自动回到原会话，若不会则需改成 `sendMessage(groupChatId, ...)`）。

**验收要点（切片 E）**
- 群聊中仅"被 @ 的 bot"消息被处理，其余群消息忽略。
- 群聊下 `/help`、`/status`、`/sessionlist` 等只读命令可用；`/batch` 在群聊返回不支持提示。
- 同一群内每个用户可各自绑定会话（或整群共享一个会话，需明确策略并记录在 doc）。

### 切片 F —— 主动投递与结果产物回传（跨切片）

| 能力 | 可复用模块 | 接通方式 |
| --- | --- | --- |
| 主动投递文本 | 已有 `sendProactiveText`（runtime/controller） | 保持；补 host 侧 delivery-service/HTTP/RPC 接线（`plugin-src/host/delivery-*.mjs`，参照其它渠道） |

| 连接测试/主动投递目标记忆 | `shared/connection-test.mjs`（`rememberConnectionTestTarget`/`connectionTestTarget`/`connectionTestMessage`/`connectionTestTargetUnavailable`） | 替代 controller 里手写的 `connectionTestText`，统一发到"最近记忆的目标"，并配 `publicConnectionTestResult` |

- 主动投递（调度/订阅）能按目标 chatId 发送；目标未记忆时返回 `connectionTestTargetUnavailable` 提示。
- 连接测试发送到最近一次与 bot 互动的私聊目标。

### 切片 H —— 入站消息深度解析（引用/合并消息）（跨切片）

| 能力 | 参考实现 | 说明 |
| --- | --- | --- |
| 引用消息（msgType=10） | `@youdu/openclaw-youdu` `src/message-prepare.ts`（`formatMessageWithReference`/`parseDecodedMessage`） | `youdu/inbound.mjs` 目前明确"预留后续实现"；需把 `body.raw.decoded` 的引用消息展开为 text+media |
| 合并聊天记录（msgType=12） | openclaw `formatMergedText`/`ParsedMergedResult` | 同上 |
| 通用深层解析 | openclaw `message-prepare.ts` | dsh-im `youdu/inbound.mjs` 是简化版移植，注释承认只覆盖最小闭环 |

**验收要点（切片 H）**
- 引用一条之前的消息时，入站上下文能带上被引用内容与图片来源。
- 转发/合并的聊天记录能展开为可读文本，供模型理解上下文。

## 4. 实现分工建议（与调度一致）

- **t2（切片 A + 命令相关 D/E 部分）**：核心命令补齐 + 命令识别器 + 命令权限门控 + 群聊 addressed 判定。**前置**：需要 `YouduBridge` 持有 `HarnessApprovalQueue` 与否等不在 t2 范围；但命令识别器与 `control: {owner,key}` 是 t2 与 t3 共用基础，建议在 t2 先把 `askOptions.control` 补齐。
- **t3（切片 B/C + 交互相关 D/E）**：审批/提问/流式/失败提示。依赖 t2 的 `control` 与命令识别器落地。
- 跨切片的 **访问策略（D）、群聊（E）、主动投递（F）、上下文增强（G）、深度解析（H）** 建议在 t2 完成后作为独立切片实现（可新增任务），避免 t2/t3 一次塞入过多。

## 5. 风险 / 需要先确认的点

1. **流式与状态反应**：有度 WebSocket 是否支持"编辑已发消息/加反应"？openclaw 与 dsh-im 协议均未见 update/edit/recall 原语，需实测或读 `media.mjs`/protocol 确认。若不支持，流式降级为"分片发送"或"一次性 markdown"，并在文档记录降级理由。
2. **群聊回复路由**：`respond_msg(reqId)` 是否自动回到原群会话；若不会，需用 `sendMessage(groupChatId, body)` 主动发送到群。
3. **群聊 @ 判定**：有度入站帧中"被 @ bot"的判定字段与 openclaw 是否一致（`atUser`/`at`/rawEventType 等价物）。
4. **`YouduStateStore` 与 `ConversationStateStore` 差异**：如需统一语义，评估是否把状态存储升级为共享实现，避免部分共享模块（如 `harness-session-binding`）因 state 接口不匹配而无法复用。
