# 有度群聊上下文缓存方案

日期：2026-09-10。代码基线：`feat/youdu-delivery`（v4.17.1）。状态：已实施，待实机验收。

需求来源：有度渠道实机观察——群聊里没有 @ 机器人的消息不会进入模型，被 @ 时模型只看到当前这一条和引用内容，缺少"最近发生了什么"。参考实现为 openclaw 的 group history（`openclaw/dist/reply-history-*.js` 与 `docs/channels/group-messages.md`）。

## 1. 语义（对齐 openclaw）

openclaw 的群聊上下文是 **pending-only**：只缓存"没有触发回复"的群消息，在被唤醒的那一轮把缓存包进 `[Chat messages since your last reply - for context]`，当前消息跟在 `[Current message - respond to this]` 之后；这一轮结束后清空缓存（消息已经写进会话历史，不再重复注入）。默认 50 条，按会话分桶，`historyLimit: 0` 关闭。

本方案保持同一语义：

| 环节 | 行为 |
| --- | --- |
| 缓存对象 | 群里没有寻址机器人的消息（mention 模式下即未 @ 机器人的消息） |
| 缓存时机 | 入站帧通过渠道去重与访问判定之后立刻记录；不等待队列 |
| 注入时机 | 寻址消息真正要提交给 Harness 之前（命令、审批、提问等控制链路不注入） |
| 注入形式 | 上下文块前置在正文之前，块后紧跟 `[Current message - respond to this]`；`<dsh_im_source>` 等其余内容保持原有顺序 |
| 消费时机 | 该回合结束（成功或失败）后只消费本次注入的那批条目 |
| 存储 | 进程内内存，按会话 key 分桶，重启即清空 |

## 2. 容量与预算

- 条数：默认 50，取值范围 0–200，`0` 表示关闭；`enabled` 与 `limit` 同时生效（`enabled === true && limit > 0`）。
- 单条正文：300 码点，超出截断并加 `…`；正文折叠为单行，去掉控制字符。
- 单次注入块：4000 码点，超出从最旧一条开始丢弃，始终保留离当前消息最近的内容。
- 会话分桶：最多 1000 个会话，超出按插入顺序淘汰最旧（命中会刷新 LRU）。
- 同一 `messageId` 重复到达只入缓存一次（非寻址消息不会被 `markSeen` 覆盖，因此需要按消息 ID 去重）。

## 3. 媒体与文件

群里未寻址消息的图片、文件、语音、视频会**用与提示链路相同的媒体下载接口**（`/cgi/bot/file/download`）取回，落到该 bot 工作区的临时目录：

```text
<workspace>/.dsh-im/group-context/<群目录>/<yyyyMMdd-HHmmss-消息id>/<序号-文件名>
```

- 群目录保留有度会话 id 的花括号形态（`{0798E01E-…}`），便于照着客户端会话 id 翻目录；其余不安全字符替换为下划线，禁止 `..` 越界。
- 落盘是异步的：条目先记入缓存，附件到位后通过 `attachFiles` 补清单，注入时取快照。
- 被 @ 时追加附件清单块 `<dsh_im_group_files>`（名字 + 工作区相对路径 + 发送者 + 时间），模型可按相对路径读取，或按需移动到别处。
- 下载失败、超时（默认最多等 10 秒，`groupHistoryStagingWaitMs`）或群被拒绝时只保留文本占位，不影响回复。
- 数量与大小不额外限制；保留期默认 7 天（`groupContextRetentionHours`，`-1` 永久、`0` 下次清理即删），清理由写入路径按间隔节流触发（默认 6 小时，`groupContextSweepIntervalMs`），并在下载期间用 in-flight 标记保护未写完的目录。
- 私聊消息与当前 @ 消息自带的附件仍走既有入站文件管线，与本缓存无关。

## 4. 隐私与访问边界

- **只缓存群访问规则允许发给机器人的消息**：与寻址消息走同一套判定（按群规则 → 共享群聊访问设置 → owner 回退）。被拒的群、被拒的发送者，其消息一律不入缓存，也不会出现在注入块里。
- 群被设为 `disabled` 时，机器人根本不进入模型流程，缓存与注入都不发生。
- 设置读取失败的场景按"关闭"处理（fail-closed），宁可不带上下文。
- 注入块只包含发送者显示名、时间和正文；附件清单只含文件名与工作区相对路径。
- 附件只在群规则允许、缓存开启时下载；下载到的文件落在该 bot 工作区的临时目录，按保留期清理。
- 缓存只作用于群聊；私聊路径行为不变。
- 关闭开关只停止后续缓存与下载，不删除已经写进 Harness 会话历史的内容与已下载的临时文件（后者按保留期清理）。

## 5. 设置与配置

- 设置页：机器人卡片上的「群聊上下文」面板，包含启用开关与缓存条数（0 = 不缓存），保存后即时生效，不重连机器人、不重建会话。
- 存储：`bots/settings.json` 中该机器人的 `groupHistory: { enabled, limit }`；旧文件缺该字段时读取为默认值，首次读取不改写文件。
- RPC：`bot.group-history.set`，载荷 `{ botId, config: { enabled, limit } }`，严格校验（字段完整、`limit` 为 0–200 整数）。
- 默认值：启用、50 条（与 openclaw 的 `messages.groupChat.historyLimit` 默认一致）。
- 附件保留期：插件配置 `groupContextRetentionHours`（默认 168 小时 = 7 天，`-1` 永久保留，`0` 下次清理即删）、`groupContextSweepIntervalMs`（默认 6 小时）、`groupHistoryStagingWaitMs`（默认 10 秒）；群聊附件数量与大小不额外限制。

## 6. 实现落点

1. `src/channels/shared/group-history.mjs`：配置校验/归一化、历史块与附件清单块格式化、进程内缓冲（record / snapshot / attachFiles / consume / clear）。不依赖 Node API，供 Host 与设置页共用。
2. `src/channels/shared/group-context-files.mjs`：群聊附件的落盘与清理（目录布局、名字净化、逐文件写入、in-flight 保护、按保留期 sweep），复用 `inbound-file.mjs` 的名字净化与目录名解析。
3. `src/channels/youdu/youdu-bridge.mjs`：入站侧记录未寻址的群消息并异步下载附件；提交前等一次在途下载、取快照并前置注入历史块与附件清单；回合结束后消费该快照。
4. `src/channels/youdu/settings-store.mjs`、`youdu-controller.mjs`：每机器人持久化与 `updateGroupHistory`。
5. `plugin-src/host/channels/shared/group-history-rpc.mjs`、`plugin-src/host/channels/youdu/rpc.mjs`：端点与载荷校验。
6. `plugin-src/host/channels/youdu/production.mjs`、`src/channels/youdu/youdu-runtime.mjs`：把实时设置 provider 与按 bot 工作区落盘的附件 provider 传到 bridge。
7. `plugin-src/client/group-history.js` 与有度设置页接线：设置页面板。

## 7. 与既有能力的边界

- **不改变群聊响应判定**：mention 模式下未 @ 机器人的消息依然不回复，只是被记下来当上下文；`all` 模式下每条群消息本来就进模型，缓存不再有额外作用（沿用 openclaw 语义：已触发回复的消息不进 pending 缓存）。
- **不取代 Harness 会话历史**：会话历史仍是连续对话的主来源；本缓存只补"机器人被唤醒之前群里发生了什么"。
- **不与上下文增强合并**：`<dsh_im_source>` 描述当前消息来源，群聊上下文是历史内容，两者可以同时存在，顺序为上下文块 → 当前消息（含来源块）。
- **不覆盖 `/history` 命令**：`/history` 读的是 Harness 会话历史（私聊、最多 5 条），与本缓存无关。
