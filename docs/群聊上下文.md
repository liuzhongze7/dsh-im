# 群聊上下文

在有度机器人卡片中点击「群聊上下文」，可以决定是否缓存群里没有 @ 机器人的最近消息，以及缓存多少条，点击「保存」后即时生效。默认开启，最近 50 条；把条数填 0 或关闭开关就不再缓存，两者都不需要重连机器人或重建会话。

开启后，群里没有寻址机器人的消息会按聊天顺序被记下来；当有人 @ 机器人时，插件把这些消息作为上下文块附加在当前消息之前，再交给模型：

```text
<dsh_im_group_history note="...">
[2026-09-10 14:12] 张三: 下午三点评审，谁去
[2026-09-10 14:13] 李四: 我去
</dsh_im_group_history>

[Current message - respond to this]
帮我整理一下
```

这一轮结束后这批消息就被消费掉，不会重复注入——它们已经作为对话的一部分写进了当前 Harness 会话。缓存期间新到的群消息留给下一轮。缓存只作用于群聊：私聊消息、命令、审批和提问回答的控制链路都不受影响；群聊未 @ 机器人的消息依旧不会触发回复，只是成为上下文。

## 图片与文件

群里未 @ 机器人的图片、文件、语音和视频会**用与消息附件相同的媒体接口下载下来**，落到该机器人工作区里的临时目录：

```text
<工作区>/.dsh-im/group-context/<群>/<20260910-141230-消息id>/01-photo.png
```

被 @ 时，除了历史文本块，插件还会追加一份附件清单：**清单是每次注入时从磁盘重建的**，列出该群保留期内最近的消息附件（默认最近 10 条，可用 `groupContextRecentLimit` 调整）：

```text
<dsh_im_group_history note="...">
[2026-09-10 14:12] 张三: [图片] photo.png
</dsh_im_group_history>
<dsh_im_group_files>
{"description":"Attachments staged for this group from earlier messages; paths are relative to the current Harness workspace. Older attachments stay in the same directory and can be listed on demand.","directory":".dsh-im/group-context/{0798E01E-...}","files":[{"name":"photo.png","path":".dsh-im/group-context/.../01-photo.png","sender":"张三","time":"2026-09-10 14:12"}]}
</dsh_im_group_files>

[Current message - respond to this]
这张图什么意思
```

因为清单来自磁盘而不是内存，三种情况依然可用：**插件重启之后**（文本缓存清空、文件还在）、**上一轮已经消费过清单之后**、以及**下载慢于等待上限时**（文件落盘后，下一次 @ 就能看到）。清单块同时告知这个目录的存在，模型可以自己列目录、读取，或把文件移动到需要的位置。

| 情况 | 表现 |
| --- | --- |
| 下载成功 | 文本行 + 清单（名字、工作区相对路径、发送者、时间） |
| 下载失败 | 只保留文本占位，回复流程不受影响 |
| 下载慢于等待上限 | 本轮清单里没有它，落盘后下一轮出现 |
| 消息重投 | 同一消息只下载一次 |
| 群被访问规则拒绝、开关关闭或条数为 0 | 不下载、不落盘 |
| 私聊消息 | 走原有入站文件管线，与本缓存无关 |

附件数量与大小不做额外限制（与消息附件一样的口径）。文件是临时文件，会按保留期清理：默认保留 7 天，可用插件配置 `groupContextRetentionHours` 调整（`-1` 永久保留，`0` 表示下次清理即删除）。清理与下载共用同一条写入路径：每次落盘新附件时按间隔（默认 6 小时，可用 `groupContextSweepIntervalMs` 调整）顺手清理过期目录，因此长期没有新附件写入时，清理会推迟到下一次写入。

## 命令

群里用得最多的是三条命令（都需要 @ 机器人，与其他命令一样受群访问规则和命令权限约束；私聊发送只会得到一条说明）：

| 命令 | 作用 |
| --- | --- |
| `/context` | 查看本群上下文缓存状态：开关与条数、待带入的消息数、本轮可带入的群附件数、附件保留期。 |
| `/context clear` | 清空本群待带入的**消息**；已下载的群附件仍保留在工作区，按保留期自然过期。 |
| `/new` | 换一个全新 Harness 会话，并同时清空本群待带入的消息——「不想被之前的群聊带偏」时用它最彻底。 |

三条命令都在本地处理，不会作为提问发给模型（`/new` 按定义会重新绑定会话）。群里发 `/help`、`/status` 同样会正常回复。

## 边界与默认值

| 项目 | 行为 |
| --- | --- |
| 生效条件 | 开关开启且条数大于 0；条数范围 0–200，默认 50。 |
| 只缓存什么 | 群访问规则允许发给机器人的消息：按群规则、共享群聊访问设置和所有者判定，与寻址消息同一套逻辑；被拒绝的群和发送者不入缓存。 |
| 单条长度 | 正文按 300 字截断（超出标注 `…`），折叠为单行。 |
| 单次注入 | 最多 4000 字，超出时从最旧一条开始丢弃，始终保留离当前消息最近的内容。 |
| 存储位置 | 进程内内存，按会话分开保存，插件重启即清空；不写入磁盘，也不写入设置文件。 |
| 重投消息 | 平台重投同一条消息不会重复入缓存。 |

「群聊上下文」只补"机器人被唤醒之前群里发生了什么"，不取代 Harness 会话历史，也不等同于 `/history`：`/history` 读取的是当前私聊绑定的 Harness 会话历史（最多 5 条），与群消息无关。它与「上下文增强」可以同时开启，注入顺序为群聊上下文块 → 当前消息（含 `<dsh_im_source>` 来源块）。

## 隐私提示

被缓存的群消息正文、发送者显示名和时间会随当前消息一起交给模型，并留在当前 Harness 会话历史中；关闭开关只停止后续缓存与注入，不删除已经写入历史的内容。如果群里有不适合进入模型的内容，请关闭该功能，或把该群设为不被机器人接收。

当前只有有度渠道接入了群聊上下文；其余渠道保持原有行为。
