# 群聊上下文

在有度机器人卡片中点击「群聊上下文」，可以决定是否缓存群里没有 @ 机器人的最近消息，以及缓存多少条，点击「保存」后即时生效。默认开启，最近 50 条；把条数填 0 或关闭开关就不再缓存，两者都不需要重连机器人或重建会话。

开启后，群里没有寻址机器人的消息会按聊天顺序被记下来；当有人 @ 机器人时，插件把这些消息作为上下文块附加在当前消息之前，再交给模型：

```text
<dsh_im_group_history note="...">
[2026-09-10 14:12] 张三: 下午三点评审，谁去
[2026-09-10 14:13] 李四: 我去
</dsh_im_group_history>

[Current message - respond to this]
帮我整理一下
```

这一轮结束后这批消息就被消费掉，不会重复注入——它们已经作为对话的一部分写进了当前 Harness 会话。缓存期间新到的群消息留给下一轮。缓存只作用于群聊：私聊消息、命令、审批和提问回答的控制链路都不受影响；群聊未 @ 机器人的消息依旧不会触发回复，只是成为上下文。

## 边界与默认值

| 项目 | 行为 |
| --- | --- |
| 生效条件 | 开关开启且条数大于 0；条数范围 0–200，默认 50。 |
| 只缓存什么 | 群访问规则允许发给机器人的消息：按群规则、共享群聊访问设置和所有者判定，与寻址消息同一套逻辑；被拒绝的群和发送者不入缓存。 |
| 单条长度 | 正文按 300 字截断（超出标注 `…`），折叠为单行。 |
| 单次注入 | 最多 4000 字，超出时从最旧一条开始丢弃，始终保留离当前消息最近的内容。 |
| 存储位置 | 进程内内存，按会话分开保存，插件重启即清空；不写入磁盘，也不写入设置文件。 |
| 重投消息 | 平台重投同一条消息不会重复入缓存。 |

「群聊上下文」只补"机器人被唤醒之前群里发生了什么"，不取代 Harness 会话历史，也不等同于 `/history`：`/history` 读取的是当前私聊绑定的 Harness 会话历史（最多 5 条），与群消息无关。它与「上下文增强」可以同时开启，注入顺序为群聊上下文块 → 当前消息（含 `<dsh_im_source>` 来源块）。

## 隐私提示

被缓存的群消息正文、发送者显示名和时间会随当前消息一起交给模型，并留在当前 Harness 会话历史中；关闭开关只停止后续缓存与注入，不删除已经写入历史的内容。如果群里有不适合进入模型的内容，请关闭该功能，或把该群设为不被机器人接收。

当前只有有度渠道接入了群聊上下文；其余渠道保持原有行为。
